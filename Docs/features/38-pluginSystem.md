# 38 插件与模块系统

## 1. 产品定位

插件系统是 Sprak Capture 的受支持扩展内核。第三方开发者无需修改宿主源码，即可扩展流量处理、协议解析、录制裁决、事务展示、命令和自动化行为。

目标是提供像游戏 Mod 一样自由、可组合、可配置的开放宿主。插件作者可以选择进程内 Native、Native Worker、Sidecar 或 Wasm；能力清单只负责告诉用户插件会使用哪些接口，不作为功能门禁。宿主维护阶段协议、生命周期、执行顺序和可诊断性，不替插件作者限制业务行为。

### 1.1 开放可信 Mod 模式

- 安装并启用即表示用户信任该 Mod；宿主不逐项弹出能力授权，也不因能力清单缺项拒绝动作。
- 任意模块类型都可以订阅任意公开阶段，模块类型只用于开发工具、界面分类和贡献发现。
- 进程内 Native 可以直接获得最高性能和宿主开放 ABI；工作进程、Sidecar 与 Wasm 是作者自行选择的部署方式，而不是强制隔离等级。
- `capabilities` 接受作者自定义字符串，仅用于自描述；`limits` 作为作者运行说明保留。宿主不执行能力授权、并发上限、调用超时、输出配额、存储配额或自动熔断。
- 宿主仍校验事件身份、代际、协议字段和动作结构，因为这些属于调用契约而非插件权限限制。

开发 API 以 [插件与模块开发 API](../pluginHookApi.md) 为准；开发者完整旅程见 [插件与 Mod 开发者体验规范](../pluginDeveloperGuide.md)；当前实现与迁移缺口见 [现状与迁移审查](../pluginSystemAudit.md)；执行计划见 [插件系统实施计划](../Plan/Plugin/PLUGIN-full-plan.md)。

## 2. 设计目标

1. 覆盖服务、连接、TLS、HTTP、WebSocket、TCP、UDP、DNS、录制、导入导出和 UI 全阶段。
2. 插件可以观察、修改、拒绝、重定向、生成响应、标注和贡献展示。
3. 多插件执行顺序明确、用户可改、结果可审计。
4. 插件运行方式由作者选择；隔离运行时的崩溃边界由对应适配器负责，进程内 Native 与宿主共享故障域。
5. 不安装插件时不改变现有转发性能和协议语义。
6. 配置、顺序、状态和版本跨重启持久化。
7. Wasm、sidecar 和高频 Native 使用同一阶段与动作语义。
8. 桌面端、CLI、MCP 和 SDK 使用同一控制事实源。
9. 第三方开发者从空目录到发布、升级和诊断均有受支持工具链，不需要接触宿主私有实现。

## 3. 非目标

- 不把未公开的宿主内部实现承诺为稳定兼容 API；进程内 Native Mod 仍可自行调用操作系统、加载库或访问进程能力。
- 不把被动 SNIFF 副本伪装成可在线修改的数据面；需要改写时插件应选择真实代理或主动重定向阶段。
- 不替插件作者规定技术栈、进程模型、网络访问、文件访问、自定义 UI 或私有协议实现方式。

## 4. 总体架构

```text
入口 / WinDivert / SOCKS / HTTP
              │
              ▼
      协议与连接处理主路径
              │
      ┌───────┴────────┐
      ▼                ▼
 内置 ToolPipeline   ExtensionKernel
      │                │
      │        ┌───────┼────────┐
      │        ▼       ▼        ▼
      │      Wasm   Sidecar  NativeWorker
      │        │       │        │
      └────────┴───────┴────────┘
              │
              ▼
      转发 / 录制 / UI 投影
```

### 4.1 ExtensionKernel

扩展内核承担：

- manifest 和版本解析。
- 阶段匹配和执行参数。
- 用户排序和执行计划编译。
- 插件实例代际管理。
- 事件分发、生命周期代际和动作结构验证。
- 日志、指标、调用错误和诊断。
- 运行时、配置、存储和 UI 贡献注册。

主路径只依赖扩展内核接口，不感知 Wasm、sidecar 或 Native 的内部通信方式。

### 4.2 RuntimeManager

每种运行时实现相同接口：初始化、调用阶段、取消、健康检查、配置迁移、停止。插件结果只复验事件身份、代际与结构完整性后进入数据面；宿主不执行能力授权过滤。

### 4.3 ContributionRegistry

贡献注册表独立于插件进程。插件退出或被作者、用户主动停用时，命令、页签、状态项和上下文动作一次性撤销，不在前端留下失效入口。

## 5. 阶段模型

完整阶段分为：

- 服务和配置。
- 连接和目标解析。
- TLS 握手和证书选择。
- HTTP 请求、响应和流式正文。
- WebSocket 帧。
- TCP 块、UDP 数据报和 DNS 消息。
- 录制事务和清空代际。
- 检查器数据、命令与上下文动作。

阶段输入是不可变原始视图加可修改草稿。宿主保留原始值、最终值、插件链和每次动作，保证问题可以追溯到具体插件与阶段。

## 6. 内置工具与插件

内置工具和插件共享同一逻辑阶段，但职责不同：

| 类型 | 适用 |
|---|---|
| 内置工具 | 通用、稳定、产品必须维护的 Map、Rewrite、断点、节流、录制规则 |
| 插件模块 | 私有协议、行业适配、自定义自动化、解码、专用展示 |

HTTP 阶段由 `ToolPipeline` 提供固定主槽，扩展内核在明确的 `extensionsBefore`、`extensionsAfter` 槽执行。插件不能插入录制代际提交和连接资源回收之间的内部临界区。

## 7. 开放能力模型

插件声明能力用于生成说明、依赖关系和管理界面摘要。用户启用插件后，该插件可以调用全部公开 Host API 并返回阶段支持的动作，宿主不执行逐能力授权。

能力说明分为：

- 流量观察、修改和拒绝。
- 连接重定向与合成 HTTP 响应。
- 录制读取、标注和控制。
- 配置、私有存储、插件目录文件。
- 出站网络访问。
- 命令与 UI 贡献。

升级新增能力时直接随新版本生效；管理页展示清单差异和调用诊断，但不弹出授权或阻止运行。

## 8. 配置与持久化

宿主使用一个权威配置文件保存：

- 已安装版本和当前版本。
- 启停状态。
- manifest 声明的能力说明。
- 用户阶段顺序和匹配规则。
- 配置 Schema 版本与非秘密配置。
- 秘密引用。
- 失败策略、作者运行说明和自动重启策略。

插件私有状态单独存储；容量、格式、迁移和回收策略由插件作者决定。更新采用暂存、验证、迁移、原子发布和旧版本保留流程。

## 9. 生命周期

```text
discovered → installed → disabled → starting → running
                                   ↘ failed
running → draining → disabled
running → updating → running(new generation)
running → draining → uninstalling → removed
```

- 启用：验证配置和公开协议契约，启动运行时，注册贡献点，再发布实例。
- 禁用：停止新事件，取消在途调用，回收贡献点和运行时。
- 重载：新实例健康后原子切换，旧实例只处理已经分配给它的事件。
- 更新：保留旧版本，迁移失败不影响当前版本。
- 服务停止：先关闭事件入口，再取消插件，不等待第三方网络 I/O。

## 10. 调度与性能

- 每阶段预编译匹配器和顺序，不在每包路径解析 manifest。
- 正文默认流式；只有明确声明完整正文且预算允许时才物化。
- 宿主不设置插件事件队列、并发、超时、输出或存储配额；插件作者直接决定线程、任务、进程和背压策略。
- 进程内 Native 在数据面同步执行，允许直接改变宿主行为；由作者承担阻塞、崩溃和资源使用结果。
- Wasm、sidecar、native worker 的进程模型、内存和故障隔离同样由作者选择，不能被宿主权限系统降级。
- 指标至少包括调用数、命中数、错误数、输入输出字节、在途调用和延迟分位数；指标只观察，不触发自动停用。

## 11. UI

插件管理页包含：

- 商店/本地安装、更新、回滚和卸载。
- 能力说明差异。
- 阶段订阅、匹配规则和拖拽顺序。
- 配置表单和秘密字段状态。
- 实例、队列、耗时、错误、日志和存储。
- 命令、协议解码器、正文查看器、媒体渲染器、导入导出器、工作区面板和开发模式。

插件可使用声明式 UI、独立 WebView、独立窗口或进程内 Native 自定义界面；只有声明式贡献承诺跨版本兼容。

## 12. 版本与包信任

- manifest、API、RPC、WIT 和贡献 Schema 独立版本化。
- 插件声明宿主和 API 兼容范围。
- 安装包包含文件摘要；签名绑定发布者和完整清单。
- 本地开发包允许未签名，但管理页持续显示来源状态。
- 更新、依赖解析和回滚使用确定性锁文件。

## 13. 当前实现状态

当前已经存在：插件目录、安装/卸载、启停持久化、配置 Schema、管理页、控制 API、MCP 基础操作、legacy Native 原始流适配器，以及完整 Native Mod、Sidecar、Native Worker 的生产加载与阶段运行时。多语言作者入口统一位于 `Server/PluginSDK/`。

完整扩展内核和开放配置模型已建立；TCP、SOCKS5 UDP 和 CONNECT 隧道已接入 `TcpChunk`、`UdpDatagram` 与 `ConnectionClosing`。Wasm 生产适配器、HTTP/TLS/WebSocket/录制全部阶段、UI 贡献和更新链仍需接入。能力清单不属于待实现授权系统，也不会成为动作门禁。

## 14. 系统验收

- 外部开发者仅使用 SDK 完成 HTTP 改写、协议解码和检查器贡献。
- HTTP、HTTPS、SSE、WebSocket、TCP、UDP、DNS 和录制阶段各有真实集成测试。
- 查看器、媒体渲染器、导入器、导出器和后台服务分别有预算、取消、卸载与跨版本测试。
- 多插件顺序、短路、修改链和审计痕迹确定可重现。
- 插件错误必须精确归因到插件与阶段；宿主不以超时、队列、配额或熔断替作者改变执行语义。
- 禁用、更新、回滚、清空录制和服务重启不存在旧代结果。
- 高流量下未命中插件路径保持基线，命中路径遵守预算且无静默丢包。
- 配置和顺序重启后保持一致。
- 桌面端、CLI、MCP 和 SDK 对同一操作返回相同事实。
- 开发者旅程的脚手架、模拟、热重载、测试、打包、签名、发布、迁移和诊断全部自动验收。
