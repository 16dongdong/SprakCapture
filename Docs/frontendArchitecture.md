# Web 前端架构

## 唯一界面源

`Server/Frontend/Web` 是浏览器模式和桌面模式共用的唯一 React 源码。Desktop 不得复制
页面组件、状态仓库、主题或接口类型。

## 界面层级（必须遵守）

```text
L0  托盘
L1  菜单栏 + 顶栏 + 底栏
L2  主工作区（概览 | 连接会话）—— 唯一常驻业务平面
L3  模态对话框（工具/代理/导入导出设置）
L4  子对话框（单条规则、确认、文件选择、断点编辑）
```

详细规范见：

- 层级与入口 → [features/35-uiShellAndNavigation.md](features/35-uiShellAndNavigation.md)
- 组件视觉/交互 → [features/36-componentSpec.md](features/36-componentSpec.md)

**对齐 Charles：** 工具与大量代理选项通过 **对话框** 配置；主窗口专注报文结构与检查器，
不做与工作台平级的「全页工具编辑器」。

**信息架构：** **能折则折、忌平铺**——说明、高级选项、次要指标等用折叠/手风琴/树展开，
默认只露出当前任务控件（见 [features/36-componentSpec.md](features/36-componentSpec.md) §1.1）。

## 页面结构

```text
应用
├─ 菜单栏（文件 / 代理 / 工具 / 视图 / 帮助）
├─ 主工作区（L2）
│  ├─ 概览
│  └─ 连接会话
│     ├─ 结构导航
│     ├─ 端点分组与事务报文
│     └─ 检查器
├─ DialogHost（L3/L4，无独立业务路由）
└─ 悬浮窗路由 /floating
```

连接会话采用单一结构工作台，不使用翻页：

- 左侧按 `host:port` 分组并直接展示真实事务报文，不提供平行的序列视图。
- 结构报文按时间增量更新并使用滚动访问完整内容。
- 右侧检查器提供概览、请求、响应和备注；请求/响应正文只在打开对应查看器时加载。
- 分隔条允许用户调整面板比例并保存到本机界面设置。

### Transaction 工作区边界

- L2 主工作区的数据模型只使用 `TransactionSummary`、`TransactionPage` 和
  `transactionId`；结构树、筛选和检查器不得读取 SOCKS `sessions[]`。
- 不保留旧 SOCKS 会话 UI、视图开关、字段投影或迁移适配器。`sessions[]` 只属于底层
  传输诊断，不是浏览器工作台的备用数据源。
- 有界集合继续读取时使用服务端返回的 `collectionToken` 与 `nextOffset`；界面不显示
  页码，也不能用请求 `limit` 推算下一偏移。
- 切换事务时，详情和正文请求必须取消或按请求身份丢弃过期结果。正文响应不得进入全局
  事务列表状态，避免大正文更新导致列表整体重渲染。
- 查看器以 Headers、Text、JSON、Hex 为基础能力；JSON 解析失败显式回退 Text，
  无正文、正文截断和头截断均使用独立状态，不以空字符串掩盖。

## 对话框架构

- 全局 `dialogStore`：`open(id, props)` / `close` / 草稿与「应用」语义。
- 工具对话框共用：总开关、规则表、添加/编辑子对话框、应用/确定/取消。
- 代理设置类对话框可用 **对话框内页签**（HTTP / SOCKS / 高级），不是主导航 Tab。
- 断点命中编辑器层级高于普通设置对话框。

## 响应式规则

- 基础字体、标题与说明字体、工具栏、状态栏、主要控件高度和关键间距统一使用
  `:root` 中的 `clamp()` 设计令牌，在保持 Charles 式密集信息层级的同时连续缩放。
- 页面使用弹性网格和 `minmax(0, 1fr)` 消化剩余空间；主窗口在 `1040×680`
  基准尺寸下保持顶部工具栏、工作区和底部状态栏互不遮挡。
- `820px` 是连接工作台的方向断点；`720px` 宽窗口采用上下分栏，分隔条改按
  纵向坐标调整高度，并独立保存窄屏高度。
- `520px` 以下进一步收紧工具栏、检查器页签和筛选栏，但不删除协议会话字段。
- 长域名、IPv6 和用户名会扩展表格或树的内容宽度，通过横向滚动完整查看，不做文本省略；
  会话详情和长错误信息允许换行。
- 结构报文不翻页；超出工作区宽度时使用横向滚动查看完整位置与类型。
- L3 对话框宽度随视口限制在 `min(960px, 92vw)`，表体内部滚动，避免整页被对话框撑破层级。

## 状态规则

界面只有一个服务状态动作。按钮文字和可用性由 `serviceState` 决定，网络失败时显示
未连接态（文案走 i18n 键），不得直接切换为成功状态。

SSE 是页面状态的默认单向事件通道；WebSocket 保留给双向交互和兼容客户端。启动、停止和配置更新
仍通过有响应语义的 HTTP 命令完成，正文、媒体和大型诊断结果继续按需读取，避免进入实时事件流。
服务状态、监听器、HTTP/SOCKS 指标、事务摘要、录制状态、进程捕获、高级重复作业和插件运行态均由
事件流主动推进；事务详情使用 Provider 级 revision 单飞缓存，媒体正文使用稳定端点按 Range 增量追加，
不得恢复固定频率轮询或按事件重复创建并发读取。
每个后台进程使用随机 `serverInstanceId`；revision 只在同一实例内比较，
`BroadcastChannel` 使用当前消息契约并拒绝旧实例回放。

工具总开关与对话框内勾选、菜单前勾选标记、顶栏开关（若有）必须与权威 snapshot 同源。

## 国际化

- 设计见 [features/42-i18n.md](features/42-i18n.md)。
- 组件使用 `t('key')`，禁止硬编码用户可见句子。
- 一等语言与功能同步补键；语言切换立即生效。
- M1d 工作台统一使用 `transactions.*`、`viewer.*`、`recording.*`；不得为已删除的
  SOCKS 会话界面新增兼容文案键。
