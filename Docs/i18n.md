# 国际化开发约定

## 语言与回退

项目把 `en`、`zh-Hans`、`zh-Hant`、`ja`、`ko`、`es`、`fr`、`de`、`pt-BR`、`ru` 作为同等级语言。Web 端的 `auto` 只表示跟随浏览器，不会作为协议语言发送；运行时回退顺序为英文、简体中文。

用户选择保存在浏览器 `localStorage` 的 `capture.ui.locale`。切换会即时更新 i18next、`html[lang]`、控制 API 的 `Accept-Language` 和事件流的 `locale` 查询参数。

## 资源位置

- Web 界面：`Server/Frontend/Web/src/locales/<locale>/app.json`
- 后端错误：`Server/Backend/locales/<locale>/errors.json`
- Web 运行时：`Server/Frontend/Web/src/i18n.ts`
- 后端协商与目录渲染：`Server/Backend/src/localization.rs`

Web 文案使用 `{{name}}` 占位符，后端错误使用 `{name}` 占位符。同一个键在十种语言中的占位符名称必须完全一致。

## 新增文案

1. 先在英文目录建立语义明确的键。
2. 同步十份语言文件，不在组件或控制处理器中硬编码用户可见文本。
3. 后端新增错误时扩展 `ErrorCode::messageKey`，并同步十份 `errors.json`。
4. 运行 `pnpm i18n:check`，确认键集合、非空值和占位符一致。
5. 运行 Web 与后端测试，至少覆盖英文、简体中文、日文切换以及请求语言协商。

## 控制 API 错误

错误响应只提供稳定的 `code`、`messageKey`、`params` 与本地化 `message`。底层框架或数据面的原始 `detail` 只保存在 `params.detail`，禁止插入任何语言的 `message`，避免非中文响应混入中文诊断或直接展示框架文本。

请求语言优先级为 `?locale=<BCP47>`、`Accept-Language`、英文。简繁中文支持脚本和区域组合标签，例如 `zh-Hans-CN`、`zh-Hant-TW`；`Accept-Language` 只接受 RFC 范围内的 `q=0..1` 且最多三位小数，无效或零权重候选不参与协商。
