# SOCKS5 独立账号服务实施计划

## 1. 依据

实施依据为 `Docs/superpowers/specs/2026-08-12-socks5-account-service-design.md`。本计划只拆分
实现顺序，不改变已经批准的账号字段、特殊值、单/多账号切换、SQLite 独占、HTTP 管理端和
账号级共享带宽语义。

## 2. 阶段一：独立账号服务核心

### 任务 1：建立 crate 和迁移框架

- 新增 `AccountService` workspace crate。
- 建立 `accountService` 二进制和可测试库入口。
- 实现数据目录解析、SQLite WAL、外键、忙等待和事务迁移。
- 验证首次创建、重复加载、数据库版本和损坏失败语义。

### 任务 2：实现管理身份

- 初始化默认 `Admin / Admin123`。
- 使用 Argon2id 保存管理密码摘要。
- 实现确定性 API Key 派生、重新派生和显式轮换。
- 实现浏览器会话修订号和身份修改事务。
- 保证完整凭据不进入数据库明文字段、日志或公开快照。

### 任务 3：实现账号仓储

- 实现账号创建、查询、分页、更新和删除。
- 实现固定密码与任意非空密码模式。
- 在 SQLite 事务内维护 `policyRevision`。
- 实现累计流量、每日统计和审计记录。

### 任务 4：实现租约注册表

- 原子执行密码、到期、零值禁用、最大连接和最大在线 IP 判定。
- 规范化 IPv4-mapped IPv6。
- 实现心跳、累计流量幂等同步、释放、超时回收和强制下线。
- 账号修改或删除后撤销不再合法的活动租约。

### 任务 5：实现 HTTP 边界

- 公共端提供登录、账号、连接、统计、审计和 OpenAPI 路由。
- 内部端仅绑定回环地址并校验进程级令牌。
- 内部端提供 bootstrap、身份修改、Key 派生、认证、同步、释放和健康检查。
- 内嵌远程账号管理静态页面。

## 3. 阶段二：SOCKS5 数据面

### 任务 6：外部认证提供器

- 在 `socks5-core` 增加非序列化的运行时认证提供器接口。
- 保持 `NoAuth`、`UsernamePassword` 和 `Plugin` 现有行为。
- 多账号模式通过内部账号服务完成认证并取得租约。
- 账号服务失联时统一认证失败，不回退到其他认证模式。

### 任务 7：租约同步

- 数据面保存账号服务实例快照。
- 每两秒批量同步租约累计值、策略变化和撤销结果。
- 正常关闭发送最终累计值；账号服务实例变化时取消旧连接。

### 任务 8：账号级共享限速

- 按 `accountId` 建立上下行虚拟时间调度器。
- TCP、BIND 和 UDP 共享账号方向额度。
- 限速等待不计入空闲超时。
- 实现公平轮转、策略热更新、零值取消和大 UDP 数据报多周期预留。

## 4. 阶段三：SprakCapture 集成

### 任务 9：账号服务监督

- `proxyService` 启动和监督 `accountService` 子进程。
- 通过匿名管道传递内部令牌并取得端点和 `serviceInstanceId`。
- 原子发布账号服务实例快照。
- 异常退出时取消多账号连接并有界重启。

### 任务 10：配置和控制 API

- `configuration.json` 增加 `multiAccount` 运行配置。
- 保留单账号配置，不在模式切换时覆盖。
- 实现开启、关闭和失败回滚事务。
- 控制快照只返回脱敏状态和 Key 指纹。

### 任务 11：SprakCapture 设置页

- SOCKS5 设置增加唯一“多账号管理”开关。
- 增加独立管理地址、端口、管理身份修改和打开页面操作。
- 开启时隐藏但保留单账号输入。
- 同步全部语言目录和前后端协议校验。

## 5. 阶段四：验收

### 任务 12：远程页面和契约测试

- 完成账号列表、编辑、详情、连接、统计、审计和管理设置页面。
- 生成并验证 OpenAPI 3.1 文档。
- 完成浏览器会话和 API Key 自动化测试。

### 任务 13：跨进程与数据面回归

- 使用系统临时 `CARGO_TARGET_DIR` 构建所有 workspace 目标。
- 验证单账号无回归、多账号首次不导入、关闭恢复和数据库复用。
- 验证并发连接/IP 上限、共享限速、账号过期、强制下线和进程异常恢复。
- 清理所有测试进程、数据库、日志和构建目录。

## 6. 提交边界

- 每个阶段必须形成可编译、可测试的完整状态。
- 提交前只暂存本计划和本功能文件，不纳入已有 `CharlesUI`、`Client` 工作区改动。
- 阶段一完成后先提交独立账号服务核心，再继续数据面和 UI 集成，便于故障回滚和评审。
