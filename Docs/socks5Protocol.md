# SOCKS5 协议

## 支持范围

数据面遵循 RFC 1928，用户名密码子协商遵循 RFC 1929：

- 版本：`0x05`
- 认证方法：`NO AUTHENTICATION REQUIRED`、`USERNAME/PASSWORD`
- 命令：`CONNECT`、`BIND`、`UDP ASSOCIATE`
- 地址：IPv4、IPv6、域名
- 响应：保留协议规定的回复码，不把所有失败折叠为普通错误

## 协商流程

```text
读取方法列表
    → 选择服务端允许且客户端声明的方法
    → 可选用户名密码子协商
    → 读取一条 SOCKS5 命令
    → 执行命令
    → 进入中继或返回失败
```

任何截断、保留字段错误、未知地址类型、未知命令或超限字段都必须终止当前控制连接，
不得继续把后续字节解释为新请求。

## CONNECT

1. 解析目标地址。
2. 在连接超时内完成 DNS 和出站连接。
3. 返回实际绑定端点。
4. 使用异步复制执行双向背压。
5. 一侧到达 EOF 时传播半关闭，不立即丢弃另一方向尚未发送的数据。

## BIND

1. 为当前控制会话建立临时监听器。
2. 返回第一阶段绑定地址。
3. 在绑定超时内接受一条远端连接，并在读取超时内完成目标域名解析和来源校验。
4. 返回第二阶段远端地址。
5. 进入双向 TCP 中继。

临时监听器必须随着控制会话、超时或服务停止而释放。

## UDP ASSOCIATE

1. 为当前控制会话建立临时 UDP 套接字。
2. 返回客户端可发送 SOCKS5 UDP 数据报的中继端点。
3. 首个合法客户端数据报确定客户端 UDP 端点。
4. 解码目标地址并转发原始负载。
5. 远端响应使用 SOCKS5 UDP 首部重新封装后返回客户端。
6. 控制 TCP 连接关闭时立即结束关联。

当前实现不接受非零 `RSV`。不支持的分片必须明确丢弃并计入指标，不能把分片字节作为
普通 UDP 负载转发。每次目标域名解析、远端 Socket 创建和发送均受连接超时约束。

## 资源限制

- 协议字段长度先验证再分配。
- UDP 数据报不得超过配置上限。
- 每个 UDP 关联最多记忆配置指定的远端地址；远端响应使用固定 32 项队列，队列满时
  立即丢包并计数，不把地址上限转换为数据报内存容量。
- 并发会话受最大连接数限制。
- 所有 TCP 会话双向转发工作缓冲的配置总预算不得超过 448 MiB；该预算不限制录制正文。
- 每个 SOCKS5 方向镜像完整字节流和分片索引；终态镜像保留到录制存储确认接管，
  以支持广播丢帧恢复，确认后会话历史释放原始镜像。
- DNS、连接、读取、空闲和关闭均具有独立超时。
- 每个会话只拥有自己的命令资源，禁止跨会话复用套接字。
