# 总体架构

## 目标

本文定义本次重构已经落地的运行架构，是当前实现的权威边界。后续网络分析能力仅记录在
[功能路线图](features/README.md) 中；路线图不代表现有接口，并且不得引入第二个
SOCKS5 公开监听入口。

服务端由三个可独立验证的层组成：

```text
Backend/Socks5
        ↓
Backend
        ↓ HTTP / SSE / WebSocket
Frontend/Web
        ↓ 构建产物
Frontend/Desktop
```

- `Backend/Socks5` 是不依赖界面的 Rust 协议与转发库。
- `Backend` 是可独立运行的 `proxyService`，负责配置、状态、控制接口和有序关闭。
- `Frontend/Web` 是唯一界面源代码，浏览器和桌面外壳不得复制页面实现。
- `Frontend/Desktop` 是 Tauri 2 外壳，只负责原生窗口、托盘、单实例和后台进程。
- `Client` 是后续客户端的独立边界，不得引用服务端内部类型。

本次重构不保留 Python、Qt、旧导入路径、旧配置适配器或双轨启动逻辑。

## 部署单元

### `proxyService`

Rust 后台进程同时承载：

1. 唯一公开 SOCKS5 数据监听器。
2. 只绑定回环地址的管理控制接口。
3. 服务状态机、会话快照和运行指标。

`BIND` 临时监听器和 `UDP ASSOCIATE` 中继套接字都属于发起它们的 SOCKS5
控制会话，不是额外的公共服务入口。

### `desktop-shell`

Tauri 桌面进程承载：

1. Windows 原生标题栏和系统按钮。
2. 主窗口、悬浮窗口和系统托盘。
3. `proxyService` 子进程监督。
4. React 静态资源加载。

关闭主窗口只隐藏到托盘。只有托盘“退出”才会停止后台服务并退出桌面进程。

### Web 前端

React 页面通过控制接口读取权威快照，并默认通过 SSE 消费单向增量事件。WebSocket 保留给需要
双向交互的客户端和兼容接入；页面状态不直接
持有套接字，也不在请求失败时伪造服务启动成功。

## 单向依赖

```text
SOCKS5 数据模型
    → 协议编解码
    → 认证与目标解析
    → TCP / UDP 命令执行
    → 会话注册表
    → 后台控制器
    → HTTP / SSE / WebSocket 契约
    → React 状态仓库
    → 页面与桌面窗口
```

反向依赖通过不可变命令、快照和事件完成，不允许界面层访问网络对象或运行任务句柄。

## 关键稳定性边界

1. SOCKS5 监听地址只有一份配置。
2. 服务启停只由后台状态机执行。
3. 活动会话关闭后必须释放出站连接、临时监听器和 UDP 套接字。
4. 运行配置、日志、会话导出和认证材料不得写入源码目录。
5. 认证口令不进入日志、会话快照、测试快照或最终报告。
6. Web 与 Desktop 共用同一套页面、状态仓库和控制契约。
